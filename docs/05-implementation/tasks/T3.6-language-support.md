## Mục tiêu

Trả lời đúng ngôn ngữ của câu hỏi cho mọi ngôn ngữ được chốt; tìm từ khóa phân tích đúng ngôn ngữ tài liệu.

## Bối cảnh

- Nếu cho phép hỏi chéo ngôn ngữ (hỏi tiếng Việt trên tài liệu tiếng Anh), tìm từ khóa ít tác dụng; dựa chủ yếu vào embedding đa ngôn ngữ.

## Phạm vi

**Trong phạm vi**

- Cấu hình phân tích `tsv` theo ngôn ngữ
- Kiểm tra ngôn ngữ câu trả lời trong eval

**Ngoài phạm vi**

- Dịch tài liệu

## Các bước thực hiện

1. Chốt cấu hình phân tích từ khóa theo ngôn ngữ tài liệu (OQ-007); nếu nhiều ngôn ngữ, cân nhắc lưu ngôn ngữ từng đoạn và dùng cấu hình tương ứng.
2. Thêm vào eval: kiểm tự động ngôn ngữ câu trả lời trùng ngôn ngữ câu hỏi.
3. Chạy eval theo từng ngôn ngữ; ghi chỉ số tách theo ngôn ngữ.

## Tiêu chí chấp nhận

- [ ] Mỗi ngôn ngữ trong OQ-007: 100% câu trả lời cùng ngôn ngữ câu hỏi; tỷ lệ đúng đạt ngưỡng của US-201 (BRD AC-013).

## Kiểm thử

- Eval tách theo ngôn ngữ.

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt và có bằng chứng (test, ảnh, log)
- [ ] Có test tự động tương ứng, chạy trong CI và xanh
- [ ] Không vi phạm quy tắc phụ thuộc (SDD §3.3); lõi không import SDK nhà cung cấp
- [ ] Lỗi dùng mã chuẩn (OpenAPI); `NOT_FOUND` và `ERROR` không bị lẫn
- [ ] Không ghi nội dung tài liệu/câu hỏi/câu trả lời vào log hoặc analytics
- [ ] Giao diện (nếu có) khớp thiết kế UI/UX và thao tác được bằng bàn phím
- [ ] Nếu chạm tới pipeline hỏi đáp: eval chạy lại không làm giảm MET-002/MET-005
- [ ] Code review đã duyệt; OpenAPI/README cập nhật nếu có thay đổi

## Ghi chú và rủi ro

- Bị chặn tới khi OQ-007 chốt; trước đó giả định một ngôn ngữ.
