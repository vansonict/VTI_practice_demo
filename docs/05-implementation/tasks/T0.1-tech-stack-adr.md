## Mục tiêu

Chọn ngôn ngữ/framework backend, frontend, thư viện đọc PDF, mô hình embedding ứng viên và cách đóng gói; ghi thành Architecture Decision Record (ADR) để mọi task sau dùng chung.

## Bối cảnh

- SAD đã chốt *kiểu* kiến trúc (modular monolith, ports & adapters, PostgreSQL + vector, SPA, container) nhưng **chưa chỉ định ngôn ngữ/framework**.
- Thư viện PDF phải trích văn bản **theo từng trang** (để trích dẫn số trang) và phát hiện được PDF có mật khẩu, PDF hỏng, PDF dạng scan (US-103).
- Mô hình embedding phải chạy được trong hạ tầng của tổ chức (SAD A-06) và hỗ trợ ngôn ngữ theo OQ-007.

## Phạm vi

**Trong phạm vi**

- ADR backend
- ADR frontend
- ADR thư viện PDF
- ADR mô hình embedding (danh sách ứng viên + tiêu chí)
- ADR đóng gói/chạy (container)

**Ngoài phạm vi**

- Chọn nhà cung cấp dịch vụ AI sinh câu trả lời (chờ OQ-009, làm ở T1.9/T3.7)
- Cấu hình hạ tầng production

## Các bước thực hiện

1. Lập tiêu chí đánh giá chung: kỹ năng sẵn có của đội, hệ sinh thái thư viện, hỗ trợ PostgreSQL + vector, sinh/kiểm OpenAPI, công cụ kiểm tra quy tắc phụ thuộc giữa module, công cụ test, giấy phép.
2. Backend: so sánh tối đa 2–3 phương án theo tiêu chí; chọn một; ghi lý do và phương án bị loại.
3. Frontend: chọn framework SPA, thư viện gọi API/bộ nhớ đệm yêu cầu, công cụ test component và E2E. Bản mẫu UI (`04-design/UI_UX_design`) là HTML/CSS/JS thuần, dùng làm tham chiếu hành vi, không bắt buộc framework.
4. Thư viện PDF: spike trên 5 file mẫu (văn bản thường, có bảng, có mật khẩu, hỏng, ảnh scan). Ghi: trích văn bản theo trang được không, phát hiện từng loại lỗi được không, tốc độ trên file lớn nhất có.
5. Mô hình embedding: lập danh sách 2–3 mô hình đa ngôn ngữ chạy nội bộ; ghi số chiều vector (ảnh hưởng schema T0.3), yêu cầu CPU/GPU, giấy phép. Chọn tạm một mô hình; xác nhận lại khi OQ-007 chốt.
6. Đóng gói: mỗi tiến trình (API, worker, embedding, reverse proxy) một container; cấu hình qua biến môi trường.
7. Viết các ADR vào `docs/05-implementation/adr/ADR-00x-*.md` theo mẫu ở phần Đặc tả.
8. Review với đội và IT/Bảo mật (giấy phép, thư viện xử lý file từ người dùng).

## Đặc tả

**Mẫu ADR**

```
# ADR-00x: <quyết định>
Trạng thái: Proposed | Accepted | Superseded by ADR-00y
Bối cảnh: <vấn đề, ràng buộc, tham chiếu SAD/SDD>
Quyết định: <chọn gì>
Phương án đã cân nhắc: <A, B, C và lý do loại>
Hệ quả: <tích cực, tiêu cực, việc phải làm tiếp>
```

**Kết quả spike PDF cần ghi** (bảng): loại file × {trích theo trang, phát hiện lỗi, thời gian}.

## Tiêu chí chấp nhận

- [ ] Có tối thiểu 5 ADR (backend, frontend, PDF, embedding, đóng gói) ở trạng thái *Accepted*, mỗi ADR có phương án bị loại kèm lý do.
- [ ] Spike PDF chứng minh: trích được văn bản theo đúng số trang trên file văn bản; phân biệt được 3 loại lỗi (mật khẩu, hỏng, scan) trên file mẫu.
- [ ] ADR embedding ghi rõ số chiều vector và đã được chuyển cho người làm T0.3.
- [ ] Không có thư viện nào có giấy phép bị IT/Bảo mật từ chối.

## Kiểm thử

- Mã spike PDF lưu kèm ADR (không cần chất lượng production) để tái lập kết quả.

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt
- [ ] Sản phẩm (tài liệu, báo cáo, dữ liệu) lưu đúng vị trí và được người liên quan review
- [ ] Các tài liệu và task bị ảnh hưởng đã được cập nhật hoặc ghi chú
