## Mục tiêu

Định nghĩa các port mà lõi phụ thuộc vào và hiện thực adapter giả lập xác định được, để phát triển và test không cần dịch vụ AI thật.

## Bối cảnh

- Nhà cung cấp AI chưa chốt (OQ-009); lõi không được import SDK nhà cung cấp.
- Adapter giả lập phải tái hiện được cả lỗi để test nhánh ERROR.

## Phạm vi

**Trong phạm vi**

- `LlmPort`, `EmbeddingPort`, `FileStorePort` (giao diện + kiểu dữ liệu + lỗi chuẩn hóa)
- Adapter giả lập cho LLM và embedding
- Adapter file store dùng hệ thống tệp cục bộ

**Ngoài phạm vi**

- `AuthPort` (T4.1)
- Adapter thật (T1.7, T3.7)

## Các bước thực hiện

1. Định nghĩa `LlmPort` với hai thao tác ở phần Đặc tả; kiểu `Evidence`, `ComposedAnswer`, `Claim`.
2. Định nghĩa lỗi chuẩn hóa: `LlmTimeout`, `LlmQuotaExceeded`, `LlmUnavailable`, `LlmInvalidOutput`, `EmbeddingUnavailable`, `StorageUnavailable`.
3. Định nghĩa `EmbeddingPort.embed(texts[]) → vectors[]` với số chiều cố định theo cấu hình.
4. Định nghĩa `FileStorePort.put(stream) → fileRef`, `open(fileRef) → stream`, `delete(fileRef)`; tên tệp theo ID, không theo tên người dùng.
5. Adapter LLM giả lập: nếu không có bằng chứng → `INSUFFICIENT_EVIDENCE`; ngược lại trả một claim trích câu đầu của bằng chứng điểm cao nhất, kèm `evidenceIds` của nó. Chế độ cấu hình: `timeout`, `quota`, `unavailable`, `invalid_output`, `cite_unknown_evidence` (trả mã bằng chứng không tồn tại, để test cổng 3).
6. Adapter embedding giả lập: vector xác định từ hash văn bản (cùng văn bản → cùng vector), đủ số chiều.
7. Adapter file store cục bộ: thư mục cấu hình được, ghi nguyên tử (ghi tệp tạm rồi đổi tên).
8. Đăng ký adapter qua cấu hình (biến môi trường), không sửa code để đổi adapter.

## Đặc tả

```
LlmPort.compose(question: string, evidence: Evidence[], history: Turn[]) -> ComposedAnswer
LlmPort.rewriteStandalone(question: string, history: Turn[]) -> { standalone: string } | { needsClarification: true }
Evidence      = { evidenceId, text, documentName, page }   // documentName/page để hiển thị, KHÔNG gửi ra ngoài nếu chính sách cấm (OQ-009)
ComposedAnswer = { status: "ANSWERED" | "INSUFFICIENT_EVIDENCE", claims: [{ text, evidenceIds: string[] }] }
Turn          = { role: "user" | "assistant", text }
```

## Tiêu chí chấp nhận

- [ ] Lõi (module `qa`, `retrieval`, `ingestion`) chỉ phụ thuộc port; kiểm tra phụ thuộc trong CI xanh.
- [ ] Đổi adapter LLM giữa giả lập và chế độ lỗi chỉ bằng biến môi trường.
- [ ] Mỗi chế độ lỗi của adapter giả lập sinh đúng lỗi chuẩn hóa tương ứng.
- [ ] Embedding giả lập trả cùng vector cho cùng văn bản và đúng số chiều cấu hình.

## Kiểm thử

- Unit test cho từng adapter giả lập và từng chế độ lỗi.
- Contract test dùng chung cho mọi adapter của một port (dùng lại ở T1.7, T3.7).

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt và có bằng chứng (test, ảnh, log)
- [ ] Có test tự động tương ứng, chạy trong CI và xanh

- [ ] Lỗi dùng mã chuẩn (OpenAPI); `NOT_FOUND` và `ERROR` không bị lẫn
- [ ] Không ghi nội dung tài liệu/câu hỏi/câu trả lời vào log hoặc analytics
- [ ] Giao diện (nếu có) khớp thiết kế UI/UX và thao tác được bằng bàn phím
