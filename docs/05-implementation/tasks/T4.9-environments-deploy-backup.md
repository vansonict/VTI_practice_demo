## Mục tiêu

Dựng môi trường `test` và `pilot` theo Deployment View, triển khai bằng một lệnh, migration chạy lại được, rollback được, sao lưu định kỳ và đã thử khôi phục.

## Bối cảnh

- `pilot` chỉ nhận dữ liệu thật sau khi G-08 đạt.

## Phạm vi

**Trong phạm vi**

- Hạ tầng test/pilot
- Pipeline triển khai
- Migration trước khi khởi động API
- Rollback về image trước
- Sao lưu CSDL + kho tệp cùng thời điểm, mã hóa
- Diễn tập khôi phục

**Ngoài phạm vi**

- HA/replica (ngoài MVP, SAD A-05)

## Các bước thực hiện

1. Dựng hạ tầng theo SAD §5.1: chỉ reverse proxy lộ ra ngoài, TLS, mạng nội bộ cho API/worker/DB/embedding.
2. Pipeline triển khai: build image có phiên bản → chạy migration → khởi động → kiểm `/readyz` → chuyển lưu lượng.
3. Migration tương thích ngược một phiên bản để rollback an toàn.
4. Sao lưu định kỳ `[TBD]` CSDL và kho tệp; lưu mã hóa; giữ `[TBD]` bản.
5. Diễn tập khôi phục vào môi trường tạm; đo thời gian; ghi vào runbook (T5.7).
6. Gắn eval hàng đêm (T1.8) vào môi trường `test`.

## Tiêu chí chấp nhận

- [ ] Triển khai phiên bản mới bằng một lệnh; rollback về phiên bản trước thành công.
- [ ] Khôi phục từ bản sao lưu cho ra hệ thống chạy được, dữ liệu khớp thời điểm sao lưu.
- [ ] Eval hàng đêm chạy trên `test` và lưu kết quả.

## Kiểm thử

- Diễn tập triển khai, rollback, khôi phục.

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt và có bằng chứng (test, ảnh, log)
- [ ] Có test tự động tương ứng, chạy trong CI và xanh
- [ ] Không vi phạm quy tắc phụ thuộc (SDD §3.3); lõi không import SDK nhà cung cấp
- [ ] Lỗi dùng mã chuẩn (OpenAPI); `NOT_FOUND` và `ERROR` không bị lẫn
- [ ] Không ghi nội dung tài liệu/câu hỏi/câu trả lời vào log hoặc analytics
- [ ] Giao diện (nếu có) khớp thiết kế UI/UX và thao tác được bằng bàn phím
- [ ] Nếu chạm tới pipeline hỏi đáp: eval chạy lại không làm giảm MET-002/MET-005
- [ ] Code review đã duyệt; OpenAPI/README cập nhật nếu có thay đổi
