## Mục tiêu

Tạo khung mã nguồn theo đúng phân rã module của SDD và cài kiểm tra tự động quy tắc phụ thuộc, để mọi task sau đặt code đúng chỗ.

## Bối cảnh

- Modular monolith: một codebase, hai tiến trình (API, worker) (SAD §1.2).
- Quy tắc: API → module nghiệp vụ → ports; module nghiệp vụ không import adapter, framework web hay SDK nhà cung cấp; adapter chỉ import port; mỗi bảng chỉ module sở hữu được ghi.

## Phạm vi

**Trong phạm vi**

- Thư mục backend theo module
- Thư mục frontend
- Cấu hình chung (biến môi trường)
- Endpoint `/healthz`, `/readyz`
- Công cụ kiểm tra phụ thuộc

**Ngoài phạm vi**

- Logic nghiệp vụ (các task sau)

## Các bước thực hiện

1. Tạo cấu trúc thư mục backend: `api/`, `modules/{iam,documents,ingestion,retrieval,qa,feedback,analytics}/`, `ports/`, `adapters/{llm,embedding,auth,filestore}/`, `shared/{config,logging,errors}/`, `entrypoints/{api,worker}`.
2. Tạo cấu trúc frontend: `src/{pages,components,api,state,i18n,styles}`; đưa design token từ bản mẫu (khối `:root`) vào `styles/tokens`.
3. Lớp cấu hình đọc biến môi trường, kiểm tra bắt buộc khi khởi động, không log giá trị bí mật.
4. Mô hình lỗi chuẩn dùng chung (`code`, `message`, `details`, `correlationId`) và middleware gán `correlationId` cho mọi request.
5. Cài công cụ kiểm tra phụ thuộc (theo ADR) với 4 quy tắc ở phần Bối cảnh; thêm một vi phạm cố ý để chứng minh công cụ bắt được, rồi xóa.
6. Viết `/healthz` (sống) và `/readyz` (kiểm CSDL + kho tệp, **không** gọi dịch vụ AI).
7. README phát triển: cách chạy, cấu trúc thư mục, quy tắc phụ thuộc.

## Tiêu chí chấp nhận

- [ ] Cấu trúc thư mục khớp SDD §3.1; mỗi module có README một dòng nêu trách nhiệm.
- [ ] Công cụ kiểm tra phụ thuộc chạy được và báo lỗi khi module nghiệp vụ import adapter.
- [ ] `/healthz` trả 200; `/readyz` trả 503 khi CSDL tắt.
- [ ] Mọi response lỗi có `correlationId`.

## Kiểm thử

- Unit test cho cấu hình và mô hình lỗi.
- Test kiểm tra phụ thuộc chạy trong CI.

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt và có bằng chứng (test, ảnh, log)
- [ ] Có test tự động tương ứng, chạy trong CI và xanh
- [ ] Không vi phạm quy tắc phụ thuộc (SDD §3.3); lõi không import SDK nhà cung cấp
- [ ] Lỗi dùng mã chuẩn (OpenAPI); `NOT_FOUND` và `ERROR` không bị lẫn
- [ ] Không ghi nội dung tài liệu/câu hỏi/câu trả lời vào log hoặc analytics
- [ ] Giao diện (nếu có) khớp thiết kế UI/UX và thao tác được bằng bàn phím
- [ ] Nếu chạm tới pipeline hỏi đáp: eval chạy lại không làm giảm MET-002/MET-005
- [ ] Code review đã duyệt; OpenAPI/README cập nhật nếu có thay đổi
