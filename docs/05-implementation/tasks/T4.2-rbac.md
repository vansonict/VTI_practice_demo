## Mục tiêu

Hai vai trò BD và MANAGER được kiểm tra phía server ở mọi route theo bảng quyền của OpenAPI; giao diện chỉ hiện chức năng theo vai trò.

## Bối cảnh

- Ảnh tham chiếu: `states/03_forbidden.png`.

## Phạm vi

**Trong phạm vi**

- Kiểm tra vai trò khai báo theo route
- Test tự động bảng quyền
- Điều hướng giao diện theo vai trò
- Trang 403

**Ngoài phạm vi**

- Quyền theo từng tài liệu (US-107, ngoài MVP)

## Các bước thực hiện

1. Khai báo vai trò cho mỗi route theo OpenAPI; mặc định từ chối nếu route chưa khai báo.
2. Sai vai trò → 403 `FORBIDDEN`; ghi `audit_log(action=access_denied)`.
3. Test tự động: sinh từ bảng quyền, gọi mọi route với mỗi vai trò và không đăng nhập.
4. Frontend: BD thấy S02, MANAGER thấy S03; mở trang không đúng vai trò → trang 403 (BD) hoặc chuyển hướng (MANAGER → S03), theo UI/UX §3.

## Tiêu chí chấp nhận

- [ ] Given vai trò BD, When gọi `/stats/weekly`, Then 403 và có bản ghi audit.
- [ ] Given vai trò MANAGER, When gọi `POST /documents`, Then 403 (theo ASM-UC-01; đổi nếu PO quyết khác).
- [ ] Test bảng quyền phủ 100% route.

## Kiểm thử

- Test bảng quyền tự động.

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt và có bằng chứng (test, ảnh, log)
- [ ] Có test tự động tương ứng, chạy trong CI và xanh
- [ ] Không vi phạm quy tắc phụ thuộc (SDD §3.3); lõi không import SDK nhà cung cấp
- [ ] Lỗi dùng mã chuẩn (OpenAPI); `NOT_FOUND` và `ERROR` không bị lẫn
- [ ] Không ghi nội dung tài liệu/câu hỏi/câu trả lời vào log hoặc analytics
- [ ] Giao diện (nếu có) khớp thiết kế UI/UX và thao tác được bằng bàn phím
- [ ] Nếu chạm tới pipeline hỏi đáp: eval chạy lại không làm giảm MET-002/MET-005
- [ ] Code review đã duyệt; OpenAPI/README cập nhật nếu có thay đổi

- ASM-UC-01 (Quản lý không upload/hỏi) là giả định chưa xác nhận; nếu đổi, sửa bảng quyền.
