## Mục tiêu

Pipeline CI chạy tự động mỗi pull request: build, lint, unit/integration test, kiểm tra phụ thuộc, lint OpenAPI, test migration.

## Bối cảnh

- Definition of Done yêu cầu test tự động và quy tắc phụ thuộc chạy trong CI.

## Phạm vi

**Trong phạm vi**

- Pipeline cho backend và frontend
- CSDL tạm cho integration test
- Báo cáo độ phủ test

**Ngoài phạm vi**

- Triển khai tự động lên môi trường (T4.9)
- Eval chất lượng hàng đêm (T1.8 gắn vào sau)

## Các bước thực hiện

1. Tạo pipeline chạy khi mở/cập nhật pull request và khi merge vào nhánh chính.
2. Các bước: cài phụ thuộc (có cache) → lint → build → unit test → integration test (CSDL PostgreSQL + vector tạm) → kiểm tra phụ thuộc → lint OpenAPI → test migration lên/xuống.
3. Xuất báo cáo độ phủ test; chưa đặt ngưỡng chặn (ngưỡng `[TBD]` chốt ở GĐ2).
4. Quét bí mật trong mã nguồn (không cho commit khóa API).
5. Bật bắt buộc CI xanh trước khi merge.

## Tiêu chí chấp nhận

- [ ] Pull request có lỗi lint, test hỏng, vi phạm phụ thuộc hoặc OpenAPI sai đều bị chặn merge.
- [ ] Thời gian pipeline được ghi lại (mục tiêu `[TBD]`).
- [ ] Commit có chuỗi giống khóa API bị CI phát hiện.

## Kiểm thử

- Mở PR thử với từng loại lỗi để xác nhận pipeline chặn.

## Definition of Done

- [ ] Mọi tiêu chí chấp nhận ở trên đạt và có bằng chứng (test, ảnh, log)
- [ ] Có test tự động tương ứng, chạy trong CI và xanh
- [ ] Không vi phạm quy tắc phụ thuộc (SDD §3.3); lõi không import SDK nhà cung cấp
- [ ] Lỗi dùng mã chuẩn (OpenAPI); `NOT_FOUND` và `ERROR` không bị lẫn
- [ ] Không ghi nội dung tài liệu/câu hỏi/câu trả lời vào log hoặc analytics
- [ ] Giao diện (nếu có) khớp thiết kế UI/UX và thao tác được bằng bàn phím
- [ ] Nếu chạm tới pipeline hỏi đáp: eval chạy lại không làm giảm MET-002/MET-005
- [ ] Code review đã duyệt; OpenAPI/README cập nhật nếu có thay đổi
