🤖 Agent làm
  • • Sinh bản nháp tài liệu theo template
  • • Audit theo rubric/checklist
  • • Vẽ sơ đồ, sinh code, chạy test
  • • Tìm mâu thuẫn, đề xuất sửa

  • • Phỏng vấn stakeholder
  • • Phê duyệt, sign-off
  • • Quyết định trade-off, ưu tiên
  • • Review & chịu trách nhiệm
PHASE 1

Intake — Tiếp nhận ý tưởng

Biến ý tưởng/yêu cầu thô thành work item có chủ sở hữu

1
Thu thập ý tưởng & bối cảnh
Agent đọc ticket/email/ghi chú, tổng hợp vấn đề, tìm prior art. Con người phỏng vấn stakeholder.
2
Soạn intent.md
7 mục: Problem, Proposed outcome, Affected users, Constraints, Success measures, Out of scope, Open questions.
3
Tạo tài liệu nền
glossary.md (thuật ngữ), stakeholders.md (ai, vai trò, concern), sources.md (nguồn dữ liệu)
4
Xác định risk tier & phê duyệt intent
PO duyệt intent. Gán owner, acceptance criteria, risk tier (Low/Medium/High).
📄 Tài liệu tạo ra
intent.md glossary.md stakeholders.md sources.md
📁 Lưu tại: docs/01-intake/ hoặc work item tracker
PHASE 2

Requirements — Thu thập yêu cầu nghiệp vụ

Tạo BRD — tài liệu yêu cầu nghiệp vụ chuẩn ISO/IEC/IEEE 29148

1
Elicitation — Khám phá nhu cầu
Agent đóng vai AI-as-client đặt câu hỏi. Con người phỏng vấn stakeholder, quan sát hiện trường.
Prompt: BRD_Elicitation_Prompt_IEEE_standard.md
2
Soạn BRD theo chuẩn
Agent sinh BRD từ template chuẩn. Bao gồm: mục tiêu kinh doanh, stakeholders, yêu cầu nghiệp vụ, ràng buộc.
Prompt: BRD_Prompt_IEEE_standard.md
3
Kiểm tra chất lượng BRD
Đối chiếu với checklist IEEE 29148. Kiểm 7 thuộc tính: Correct, Unambiguous, Complete, Consistent, Verifiable, Traceable, Prioritised.
Checklist: BRD_IEEE_29148_Checklist.xlsx
4
PM/PO Review & Approve
PM/PO xác nhận nội dung. Baseline BRD trong git.
📄 Tài liệu tạo ra
BRD.md interviews/*.md
📁 Lưu tại: docs/02-requirements/
PHASE 3

Analysis — Phân tích yêu cầu

Từ BRD → SRS/PRD + User Stories — yêu cầu cụ thể, đo được, kiểm thử được

1
Phân tích BRD → Đặc tả yêu cầu
Agent phân tích BRD, tách FR/NFR, gán mã ID, kiểm mâu thuẫn. Con người xác nhận ý nghĩa nghiệp vụ.
Prompt: PRD_Prompt_IEEE_standard.md
2
Viết User Stories + Acceptance Criteria
"As a [role], I want [capability], so that [benefit]". Mỗi story gắn FR-ID, có AC rõ ràng.
3
Audit chất lượng yêu cầu
Đối chiếu PRD checklist IEEE 29148. Mỗi yêu cầu phải: cần thiết, đơn nghĩa, đầy đủ, nhất quán, kiểm chứng được, truy vết được.
Checklist: PRD_IEEE_29148_Checklist.xlsx
4
Traceability + Review + Baseline
Lập ma trận truy vết BRD→SRS→US. PM/PO + Tech Lead review. Baseline trong git.
📄 Tài liệu tạo ra
SRS.md / PRD.md USER_STORIES.md traceability.md
📁 Lưu tại: docs/03-analysis/
PHASE 4

Design — Thiết kế kiến trúc & mô hình

SAD + Blueprint + Sơ đồ 4+1/C4 + ADR + UI/UX + Interface contracts

1
SAD — Kiến trúc hệ thống (arc42 / IEEE 1016)
Agent sinh SAD theo 12 mục arc42. Ghi building block CMP-xx, quyết định kiến trúc, quality attributes.
Prompt: SAD_Prompt_IEEE_standard.md · Checklist: SAD_IEEE_1016_Checklist.xlsx
2
Mô hình hóa 4+1 Views
Logical (class) · Process (sequence/activity) · Development (component) · Physical (deployment) · Scenarios (use case)
Mỗi view có prompt + checklist UML 2.0 riêng
3
ADR + Blueprint + Interface + Data Model
≥3 ADR cho quyết định khó đảo ngược. Blueprint (IEEE 1016). OpenAPI contracts. Database design (SQL/NoSQL/Vector).
Prompt: bluePrint_design_prompt.md, apiDesign_prompt.md, databaseDesign_*.md
4
UI/UX Design + Cross-view Audit + Review
UI/UX design với personas, WCAG 2.1 AA. Chạy audit nhất quán giữa các view. Tech Lead + Architect review.
Prompt: UI-UX-Design_prompt.md
📄 Tài liệu tạo ra
SAD.md ADR-*.md blueprint.md diagrams/*.drawio openapi.md data/model.md UI_UX_design/ elements.yaml
📁 Lưu tại: docs/04-design/
PHASE 5

Planning — Lập kế hoạch thực thi

Từ SAD + User Stories → Plan chia nhỏ thành vertical slices build được

1
Phân rã công việc (Work Breakdown)
Agent phân tích SAD + USER_STORIES → chia thành task nhỏ. Mỗi task đủ nhỏ cho agent xử lý trong vài vòng lặp.
2
Xác định thứ tự, phụ thuộc, ước lượng
Mỗi task có: owner, FR-ID, dependencies, estimate, file chạm, rủi ro. Ưu tiên vertical slice.
3
Ghi nhận quyết định & rủi ro
Record decisions with rationale. Ghi open risks, unknowns, gaps — mỗi item có owner.
4
PM/PO + Tech Lead Review
PM/PO duyệt scope & sequencing. Tech Lead duyệt technical feasibility.
📄 Tài liệu tạo ra
PLAN.md tasks/*.md
📁 Lưu tại: docs/05-implement/
PHASE 6

Implementation — Phát triển mã nguồn

Mỗi User Story = một vòng SPECIFY → GENERATE → VERIFY → REFINE

1
SPECIFY — Đọc US + AC, viết test trước
Đọc docs/ như nguồn sự thật. AC → test case (TDD). Cấu hình AGENTS.md: stack, conventions, điều cấm.
2
GENERATE — Code theo vertical slice
DB → API → UI → test, mỗi slice chạy được. Commit nhỏ, Conventional Commits, gắn US/FR trong message.
3
VERIFY — Lint · test · CI
L0: format, lint, type check, unit test, secret scan, dependency scan, build. Tất cả deterministic.
4
REFINE — Sửa nhỏ nhất theo phát hiện
Lặp lại cho đến khi mọi AC xanh. Cập nhật traceability.md: US ↔ FR ↔ code ↔ test.
📄 Tài liệu tạo ra
Source code (app/) Tests (tests/) AGENTS.md traceability.md ↻ ADR mới (nếu có)
📁 Lưu tại: app/, tests/, root repo
PHASE 7-8

Verify & Review — Kiểm chứng & Phê duyệt

Tháp đảm bảo chất lượng: L0 (máy) → L1 (agent) → L2 (người) → L3-L4 (rủi ro cao)

🔍 Verification (Phase 7)

L0 — CI tự động: lint, type, test, coverage ≥70%, secret scan, build <10 min
L1 — Agent review: review theo rubric, trích dẫn dòng lỗi, chạy trên diff, không có quyền merge
Test plan: dùng testPlan_prompt.md + Test_Plan_IEEE_829_Checklist.xlsx
Code review checklist: Code_Review_IEEE_1028_Checklist.xlsx

✅ Code Review (Phase 8)

L2 — Human review: 1 approver ≠ author. PR ≤ 400 dòng. Đọc diff, không đọc tóm tắt
Rubric 7 tiêu chí: Đúng AC, Test, Thiết kế, An toàn, Hiệu năng, Dễ đọc, Truy vết (≥10/14 mới merge)
L3-L4: Inspection cho diff rủi ro cao (auth, PII, tiền). Demo validation với stakeholder
Agent KHÔNG được: approve, merge hoặc deploy
📄 Tài liệu tạo ra
test-report CI log review-record.md PR + approval coverage report
📁 Lưu tại: PR/work item + docs/07-verification/
PHASE 9-11

Release · Operate · Decommission

Deploy có kiểm soát, vận hành có giám sát, nghỉ hưu có kế hoạch

🚀 Release (Phase 9)

  • • Confirm artifact = reviewed commit
  • • Release notes, feature flags
  • • Staged rollout / canary
  • • Human authorize deploy
  • • Monitor health indicators
  • • Rollback plan sẵn sàng

⚙️ Operate (Phase 10)

  • • Agent giám sát telemetry, logs
  • • Incident → control band → intent.md mới
  • • Agent KHÔNG thay đổi production
  • • Post-incident review
  • • Feed lessons → tests, docs, SOP

🏚 Decommission (Phase 11)

  • • Agent inventory dependents, data
  • • Verify data retention/deletion
  • • Revoke access & credentials
  • • Update diagrams & docs
  • • Owner sign-off retirement
📄 Tài liệu tạo ra
release record runbooks dashboards incident record decommission record
📁 Lưu tại: docs/09-release/, docs/10-operations/, docs/11-decommissioning/

📋 Dòng chảy tài liệu — Toàn bộ Agentic SDLC

Mỗi bước tạo ra artifact → artifact đó là đầu vào cho bước sau → chuỗi commit = audit trail

Phase Tài liệu (theo thứ tự) Chuẩn / Prompt Người duyệt
1. Intake intent.md → glossary.md → stakeholders.md → sources.md AI-native SDLC model PO
2. Requirements BRD.md IEEE 29148 · BRD prompts PM/PO
3. Analysis SRS.md / PRD.md → USER_STORIES.md → traceability.md IEEE 29148 · PRD prompts PM/PO + Tech Lead
4. Design SAD.md → ADR-*.md → diagrams/ → blueprint.md → openapi.yaml → data/model.md → UI_UX/ IEEE 1016 · ISO 42010 · UML 2.0 · 4+1 · C4 Architect + Tech Lead
5. Planning PLAN.md → tasks/*.md — PM/PO + Tech Lead
6. Build AGENTS.md → app/ → tests/ → traceability.md ↻ ISO 25010 · Conventional Commits Human owner
7. Verify test-report → CI log → coverage IEEE 829 · IEEE 29119 · testPlan prompt QA + Reviewer
8. Review PR + review record → approval IEEE 1028 · Code Review checklist Reviewer ≠ Author
9–11. Release→Op→Retire release record → runbooks → incident record → decommission record ISO 12207 · ISO 9001 Release owner
⚠️ Luật bất biến: Người/agent tạo nội dung ≠ người phê duyệt. Sau baseline, mọi thay đổi phải qua change control có bản ghi.
